**Changes:**
* **The host reads the request.** The three request sentences the jobs use are read in Python, with no model call: `Add a service at (x,y) with value v.`, `Add a dependency edge from (a,b) to (c,d) with relation r and weight w.`, `Delete the service at (x,y).` A sentence of another form is an error; nothing falls back to a looser reading. * **The expression is chosen per request.** `capped` is the third run's expression for every request. **`kind`:** an add-service request may only be answered by one `ADD[x,y:v]`, an add-edge request by one `ADD[(a,b)->(c,d):name#w]` (name of 1 to 16 characters as before), a delete request by `DEL` items only (a node and edges, in any order). **`named`:** the kind and the coordinates the request names: `ADD[x,y:v]` with the x and y of the request, `ADD[(a,b)->(c,d):dep#w]` with the endpoints and the relation of the request; a delete begins with `DEL[x,y]` of the named service and may then only delete edges that touch it (the rule that a write does not delete what nobody asked for, in the grammar). In `named` the number v, the weight w and the edges of a delete are still the model's. **For all 192 jobs the oracle's own reply is inside the expression of every request** (checked in the test and again by the code at every request: a grammar that cannot say the answer is not this test).

## What this does not show
Requests in free words (the host reads the sentence the job was built from); a grammar written by someone who does not know the kinds of request; a retry on top of a grammar (no cell has one); the parity turn as a step of the loop (it is a probe, not a cell); another model, GPU, engine or cache size; dollars; a capacity in jobs per GPU; a lower bound of the cost per exact step (Q = O / M is computed, a floor of M is not shown); energy (never measured; only time); the kept chat with a grammar (not run); a hub rule in the repair (the repair's degree threshold stays 4; no deleted service of the 192 scripts has more than 3 connections, so a primal-only hub would not change a cell); jobs longer than 30 steps; the tensor-level roadmap (this test is a prompt and a grammar and trains nothing).

## How it is run
Open `python/colab/axi_provider_side_typed.ipynb` in Colab with a T4 and run the cells one at a time: it installs vLLM 0.31.0, connects Drive, fixes the output stream, loads the model with the per-request constraint, runs the safety cell (3 jobs of 3 steps with the heaviest variant, then the probe), then the seven cells in order. Each finished cell is written as `axi_provider_t_<label>.json` and copied to Drive; a cell that was cut off is run again from its start (the longest takes about 4 minutes). The last cell puts the seven cells together, reads the third run's file from the repository, prints the table, the first misses, the 17 lines and Q = O / M per cell, and offers the files for download. The Result goes below the line at the end of this page, and a result test will recompute every number in it from the saved files.
