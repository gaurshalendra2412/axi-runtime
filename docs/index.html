AXI Runtime: a host-side layer between a model and the state it edits

AXI sits on the host side, between a model and the state it edits. The model is unchanged. It is for the company that runs the model, not for end users, and it fits any LLM application that holds state: agents, chat, workflows, short jobs and long ones, from the first step. It proposes one change at a time; the host checks the proposal against the rules, completes what the rules can complete, commits it all or not at all, and shows the model the exact state again in a short prompt rebuilt from what the host holds.

Architecture by Rajnish Choubey. Tests built and run by Shalendra Gaur, with an AI coding assistant as a tool; the assistance is disclosed in the repository. Not affiliated with any model provider.

Check it in a few seconds, with no key

git clone https://github.com/gaurshalendra2412/axi-runtime
cd axi-runtime/python
python3 quickstart_replay.py

It replays the saved real replies of the 4,000-step Gemini 3.8 Flash run through the repository's own code and recomputes the held state step by step. Prefer a browser? Open the notebook in Colab. With your own Gemini key, a free one is enough, live_check.py runs the same harness live. Details: TRY_IT.md.

What was measured

ResultWhere it is written
Gemini 3.8 Flash, 4,000 steps: the state the host holds was exactly right on 4,000 of 4,000 steps. The model's own replies were exactly the ideal reply on 3,954; the other 46 were completed by the fixed repair rule.MILLION_TOKEN_TEST_HARD.md
First 400 requests of that run: replies applied as written left the right state on 85 of 400; gate and repair with AXI, 400 of 400. Cost of a step with the right state: 4.5 times lower with AXI.MILLION_TOKEN_TEST_HARD.md
Long job on Gemini 3.8 Flash: 476,835 prompt tokens a step on average with the chat kept, 2,824 flat with AXI (169 times fewer). First token past 500,000 tokens of prompt: 9.13 s against 2.27 s flat.GEMINI_LONG_TEST.md, AXI_FOR_COMPANIES.md
7B open model, four jobs of 20,000 steps: held state exact on 80,000 of 80,000; the prompt stayed near 620 tokens; a step took 0.1605 s early and 0.1651 s late.ENDURANCE_7B_TEST.md
Gate stress: 10,000,000 hostile proposals through the gate of the Python reference model; none of the 1,401,041 injection proposals was committed.GATE_STRESS_TEST.md
256 sessions on one NVIDIA L4: 105,230 exact steps per GPU hour.SESSIONS_PER_CHIP_TEST.md

Every number above is about the state the host holds. Each page says how its run was done, and the code is in the repository; the first two rows can be recomputed from the saved replies in a few seconds.

The bottlenecks people publish, next to the result

FOR_ENGINEERS.md lists what is said in public about agent context (cost and time to first token rising with context, stale context, caching, the input-to-output token ratio of agent loops, multi-turn unreliability, context rot), with the source for each, and puts next to each the result AXI measured on the same quantity.

Technical report

Design, measurements, scope, related work and references in six pages, with a DOI: doi:10.5281/zenodo.24508592 (Zenodo, 24 November 2026). The same text is in the repository as PDF and Markdown.

Related work

A commit boundary around what an agent changes is also built by others: Cordon (arXiv 2606.17573) and MemTX (arXiv 2607.23929). Their settings and evaluations differ from AXI's, and the systems have not been run against each other. See RELATED_WORK.md.
